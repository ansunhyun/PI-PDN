1. 적용 범위와 처리 흐름

SI-TDR은 Spec CSV에서 분석 시작 IC와 P/M Pin을 읽고, 설계 데이터에서 실제 Channel Path와 반대쪽 Endpoint를 찾습니다. 이후 경로에 필요한 Port와 Series 부품 모델을 적용하여 sNp와 TDR 결과를 생성합니다.

Zuken 설계 데이터 → SIW/AEDB 전처리 → Channel Path → Port → SIWave sNp → AEDT TDR → CSV·이미지

현재 고객 기본 실행은 Zuken Design Data + AEDT 2025.2입니다. 함께 제공되는 재현 Case도 전달 결과를 다시 확인하기 위한 ANF/CMP + AEDT 2025.2 입력입니다.

실행은 두 가지입니다. 실제 제품을 해석할 때는 고객의 request JSON과 Job 폴더 입력으로 실행합니다. 전달받은 재현 샘플은 각 Case 폴더의 README 순서대로 실행하면 됩니다.

2. 고객 폴더 구성

C:\SI_TDR\
├─ main.py
├─ requirements.txt
└─ core\
   ├─ config.json
   ├─ runtime.py
   ├─ channel\
   └─ preprocess\

<EDEN Job>\
├─ <external-request.json>
├─ Spec\
├─ cadFile\
├─ Stackup\
├─ BOM\
└─ Setup\
   ├─ SWS\
   ├─ SFSDF\
   └─ TDR\

request JSON의 파일 이름은 자유롭게 정할 수 있고, 그 파일이 있는 폴더가 Job 폴더가 됩니다. Spec/cadFile/Stackup/BOM 파일과 Setup 옵션 파일은 EDEN이 Job 폴더 안에 준비합니다. 즉 입력 파일은 코드 ZIP이 아니라 Job 폴더에 있습니다. 샘플 전용 시험 BOM은 고객 코드 ZIP의 운영 입력으로 포함하지 않습니다.

Windows와 AEDT 내부 경로 제한을 피하기 위해 C:\SI_TDR처럼 짧은 위치에 압축을 푸는 것을 권장합니다.

사용자가 관리하는 항목용도
<external-request.json>해석할 입력 파일 이름을 알려주는 요청 파일. DCIR과 같은 Request/CAE 형식
Spec/*.csv분석할 IC Pin, P/M Pair, 채널 및 결과 그룹을 입력
core/config.json설계 입력 방식, BOM 필수 컬럼, Port 임피던스, SYZ/TDR Profile을 설정
cadFile/ Stackup/ BOM/제품별 Zuken/ANF-CMP, STK, BOM을 staging

channel/, preprocess/ 및 main.py는 프로그램 코드이므로 일반 설정 작업에서는 수정하지 않습니다.

3. 권장 실행 순서

3.1 실행 환경 확인

  • Windows 사용자 세션에서 Ansys 및 SIWave 라이선스를 사용할 수 있어야 합니다.
  • Zuken Design Force 실행 파일과 라이선스를 사용할 수 있어야 합니다.
  • 사용할 Python 환경에 requirements.txt의 PyAEDT/PyEDB 의존성이 준비되어 있어야 합니다.
  • core/config.json의 top-level aedtVersion=2025.2와 설치된 AEDT 버전을 맞춥니다.

3.2 Python 실행 환경 요구사항

SI-TDR은 아래 의존성이 설치된 python.exe로 실행합니다. 코드 ZIP에는 Python 환경이 들어 있지 않습니다. 전용 venv를 만들어도 되고, DCIR이 이미 정상 실행되고 있다면 그 Python 환경을 공유해도 됩니다. 어느 쪽이든 실행할 때마다 venv를 별도로 활성화할 필요는 없으며, 해당 python.exe의 전체 경로로 main.py를 시작하면 됩니다.

pyaedt==0.17.2
ansys-pythonnet==3.1.0rc6
pyedb==0.50.1
Pillow==10.2.0

ansys-pythonnet==3.1.0rc6은 customer-strict AEDT Circuit을 DCIR과 같은 Windows COM 경로로 실행하는 의존성입니다. Pillow==10.2.0은 고객 패키지의 재현 가능한 설치 pin이며 PCB 캡처 이미지의 크기 정규화와 무결성 검증에 사용합니다.

실행 형태는 다음과 같습니다. <python.exe>와 코드 위치는 설치 환경에 따릅니다.

& "<python.exe>" `
  .\main.py <job>\<external-request.json> --preflight-only
Python 경로는 설정 파일에 적지 않습니다. request JSON과 core/config.json에는 Python 경로 항목이 없습니다. 실행하는 쪽(EDEN 또는 사용자)이 원하는 python.exe로 main.py를 시작하면 됩니다. EDEN에 실행 명령을 등록하는 방법은 고객 시스템 설정 영역이므로 이 문서에서 다루지 않습니다.

3.3 외부 요청 preflight(보조 진단)

cd C:\SI_TDR
python.exe .\main.py <job>\<external-request.json> --preflight-only

Spec/CAD/Stackup/BOM 입력과 SYZ/TDR 옵션 파일, AEDT 버전 설정이 모두 준비됐는지 실행 전에 확인합니다. 이 검사는 Ansys/Zuken 라이선스를 사용하지 않습니다.

3.4 고객 Reference 2025.2 Smoke(보조 진단)

python.exe .\main.py <job>\<external-request.json> --prepare-reference-only

이 명령은 Zuken 또는 ANF/CMP부터 공통 reference SIW/AEDB와 manifest까지만 생성합니다. 성공해도 후속 SYZ/TDR이 실행되었다는 뜻은 아닙니다.

3.5 고객 기본 FullBatch

python.exe .\main.py <job>\<external-request.json>

옵션 없이 이 한 줄만 실행하면 설계 전처리부터 SIWave SYZ, AEDT TDR, PCB 이미지, 결과 publish까지 전부 수행합니다. request JSON 파일 이름은 자유입니다.

3.6 전달 Case 재현

전달받은 Case를 다시 실행할 때는 그 Case 폴더의 README.md와 VALIDATION-SUMMARY.json을 따릅니다.

4. 외부 DCIR 호환 request JSON

request JSON은 DCIR과 같은 Request/CAE 형식이며 SI-TDR 전용 항목을 추가하지 않습니다. 파일 이름은 자유이고, 이 파일이 있는 폴더가 Job 폴더입니다.

{
  "Request": {
    "Model": "CUSTOMER_MODEL"
  },
  "CAE": {
    "SOC": {
      "Name": "CUSTOMER_SOC",
      "Spec": "customer_spec.csv"
    },
    "PCB": {
      "cadFile": "customer_board.zip",
      "Stackup": "customer_board.stk",
      "BOM": "customer_bom.csv"
    }
  }
}
항목설명Job-local 위치
CAE.SOC.NameSoC 이름(필수). Heaven의 Spec 선택과 EDEN 공개 결과의 socName에 사용하며 비워 둘 수 없음request JSON 값
CAE.SOC.Spec실제 Spec file 이름Spec/
CAE.PCB.cadFileZuken PCB/ZIP 또는 ANF/CMP 입력 이름cadFile/
CAE.PCB.StackupSTK 이름Stackup/
CAE.PCB.BOMCSV/XLS/XLSX BOM 이름BOM/
Spec file 이름은 자유입니다 channel.csv, spec.csv 같은 고정 이름을 쓰지 않습니다. CAE.SOC.Spec에 적은 이름의 파일을 Spec/ 폴더에서 찾아 사용합니다. 파일이 없거나 이름이 맞지 않으면 해석을 시작하기 전에 실패합니다.
SoC Name은 필수입니다 Heaven은 모델명과 CAE.SOC.Name을 조합하여 Library에서 SI-TDR_<SoC명>_<모델명>.csv 형식의 Spec을 선택합니다. SI-TDR은 CAE.SOC.Spec에 기록된 실제 파일을 사용하고, CAE.SOC.Name은 최종 EDEN 공개 결과의 requestData.socName에 기록합니다. 이 값이 없거나 빈 문자열이면 최종 결과를 outputs/로 publish하지 않습니다.

5. Spec file 작성

5.1 기본 형식

Designator,IC_Pin_No.,Function,Version,Group,Direction,Channel_Name,Polarity,Target_Impedance(ohm),Min_Spec(ohm),Max_Spec(ohm),Net_Name,IC_Pin_Name,SYZ_Option,TDR_Option
IC5001,C15,HDMI,2_0,HDMI1,RX,DATA0,M,100,90,110,HDMI1_RX0-,,SYZ_DEFAULT,TDR_DEFAULT
IC5001,A15,HDMI,2_0,HDMI1,RX,DATA0,P,100,90,110,HDMI1_RX0+,,SYZ_DEFAULT,TDR_DEFAULT

한 Differential Channel은 서로 인접한 두 행으로 작성합니다. 두 행에는 P와 M이 하나씩 있어야 하며 순서는 상관없습니다.

5.2 컬럼 설명

컬럼필수의미와 입력 규칙
Designator필수경로 탐색을 시작할 IC RefDes. 같은 Group이 여러 IC에 존재하면 이 값으로 결과를 구분합니다.
IC_Pin_No.필수해당 P 또는 M 신호의 실제 Pin 번호
Function필수HDMI, LVDS, DP, USB 등 Interface 종류
Version선택2_0 등 Interface 버전. 값이 없으면 결과 이름에서 생략됩니다.
Group필수하나의 TDR 차트에 함께 표시할 채널 묶음이며 차트 이름으로 사용됩니다.
Direction필수표시된 Designator 기준 TX 또는 RX. TDR Near/Far 방향을 결정합니다.
Channel_Name필수CLK, DATA0, DATA1, LANE0, AUX 등 자유로운 채널 이름. 영문·숫자·점·밑줄·하이픈만 사용합니다. AEDT Results의 Trace 이름과 차트 범례에도 이 값이 표시됩니다.
Polarity필수P 또는 M. 한 Pair에 각각 하나씩 필요합니다.
Target_Impedance(ohm)필수차동 기준 임피던스. HDMI/DP/LVDS 예: 100, USB 예: 90
Min_Spec(ohm)필수차트 Target band 하한. 0보다 큰 숫자
Max_Spec(ohm)필수차트 Target band 상한. Min ≤ Target ≤ Max여야 합니다.
Net_Name선택고객 참고용 Net 이름. 실제 Channel Path는 Designator와 Pin으로 설계에서 확인합니다.
IC_Pin_Name선택고객 참고용 Pin 기능 이름. 자동 경로의 기준값은 아닙니다.
SYZ_Option선택이 sNp 묶음에 적용할 SYZ Profile ID. 같은 묶음의 모든 행은 같은 값이어야 하고, 비워 두면 기본 Profile을 사용합니다.
TDR_Option선택이 Group의 TDR에 적용할 TDR Profile ID. 같은 Group의 모든 행은 같은 값이어야 하고, 비워 두면 기본 Profile을 사용합니다.

5.3 결과 파일과 차트 묶음

하나의 sNp 해석 묶음은 다음 조합에서 자동 생성됩니다.

Function + Version + Designator + Group + Direction

예를 들어 HDMI / 2_0 / IC5001 / HDMI1 / RX는 HDMI_2_0_IC5001_HDMI1_RX.s16p처럼 생성됩니다. 같은 묶음 안의 TDR 차트 이름은 Group 값인 HDMI1입니다.

Pair 작성 시 주의 인접한 두 행의 Designator, Function, Version, Group, Direction, Channel_Name, SYZ_Option, TDR_Option 및 임피던스 값은 같아야 합니다. Pin과 Polarity만 각각의 P/M 값으로 작성합니다. 같은 sNp 묶음 안에서 Channel_Name을 중복 사용하면 중단됩니다.

CSV 앞부분의 보드 이름 행, 빈 행 및 반복 헤더는 읽을 수 있지만, 유지보수를 위해 한 개 헤더 아래에 연속된 Pair로 정리하는 것을 권장합니다.

6. core/config.json 설정

6.1 설계 입력과 AEDT 버전

"schemaVersion": 1,
"aedtVersion": "2025.2",
"isZuken": true,
"DF_path": "C:\\Program Files\\Zuken\\CR-8000\\Design Force\\bin",
"exportANF": true,
"exportCMP": true,
"exportODB": true,
"exportEDB": false
항목확인 사항
aedtVersion모든 단계에서 2025.2 하나만 사용
isZukentrue면 Zuken 설계 데이터(.zip) 입력, false면 ANF/CMP 직접 입력으로 동작
DF_path고객 PC의 Zuken Design Force bin 경로
exportANF/CMP/ODB/EDBZuken 변환 산출물 선택. isZuken=true는 공통 reference를 위해 ANF/CMP가 반드시 true이고, isZuken=false이면 모두 false
tdrReport.yAxisMarginOhmSpec Target Impedance를 중심으로 한 AEDT native Report Y축 여유값. 기본값은 30 Ω

Spec, CAD, Stackup, BOM 파일명은 외부 Heaven JSON의 기존 CAE 필드에서 읽습니다. 관리자 Config에는 preprocessing.inputs나 BOM.path를 두지 않습니다.

보드 참조 프로젝트 이름도 실제 설계 입력에서 자동으로 정합니다. direct ANF/CMP 또는 ANF/CMP ZIP은 ANF/CMP pair의 파일명, Zuken design ZIP은 CAE.PCB.cadFile의 파일명을 사용합니다. 예를 들어 EAX01892301.anf/.cmp는 내부 work에 EAX01892301_ref.siw와 EAX01892301_ref.aedb/를 생성하고, 고객 outputs에는 EAX01892301_ref.siwz 아카이브만 공개합니다.

6.2 DC short/delete 정책

preprocessing.dcShort의 기본값은 DCIR DCIR.dcShort와 같은 값으로 제공합니다. 목록 값(제외 Net, 부품 이름, Component Type)은 고객 제품에 맞게 변경할 수 있습니다.

구조는 유지해야 합니다 excludeNet, shortedComp, excludePrefixes, deleteCompTypes는 명시적 문자열 목록으로 있어야 하고 shortKey는 비워 둘 수 없습니다. deleteCompTypes와 preserveCompTypes에 같은 항목을 함께 넣으면 시작 전 검증에서 중단됩니다.

6.3 Reference Net과 PCB 이미지 선택

"nets": { "reference": "GND" }

nets.reference에는 기준(GND) Net 이름을 적습니다. 이 값은 참고용 힌트이고, 실제 기준 Net은 설계 데이터에서 Ground로 분류된 Net을 근거로 프로그램이 확정합니다. 자세한 규칙은 9장을 참고하십시오.

"pcbCapture": {
  "route": { "enabled": false },
  "overview": { "enabled": false }
}
설정true일 때false일 때
route.enabledBatch별 <Batch>_PCB_Capture.jpg 생성Batch PCB Route 캡처를 계획된 상태로 건너뜀
overview.enabledJob당 보드 전체 top.jpg/bottom.jpg 생성보드 전체 Top/Bottom 캡처를 계획된 상태로 건너뜀

RC18 전달본의 기본값은 false/false입니다. 두 캡처를 모두 꺼도 SIWave SYZ, sNp, SIW/SIWZ, AEDT Circuit/TDR, JPG/CSV와 재현 프로젝트는 그대로 생성하며 FullBatch는 정상 publish까지 진행합니다. 캡처가 필요하면 해당 값을 명시적으로 true로 바꾸십시오.

Route 캡처를 켜면 Batch별로 채널 배선이 지나는 층만 켠 확대 이미지 한 장을 만듭니다. 내부 work에서는 route.png, 최종 outputs에서는 <Batch>_PCB_Capture.jpg입니다. 채널 Net은 빨간색, 주변은 회색으로 표시합니다. 경로 시작·끝 부품의 RefDes는 result_detail.json에서 확인할 수 있습니다.

오류 무시 설정은 아닙니다 enabled=false는 실행 전에 정한 정상 생략 상태입니다. true로 요청한 캡처가 실패하면 기존과 같이 FullBatch도 실패합니다. 두 항목을 선언할 때는 둘 다 Boolean으로 명시해야 합니다.

7. BOM과 Series/Array 계약

Channel Path 위의 일반 R/C/L은 종류와 값에 관계없이 0옴으로 단락합니다. RefDes가 대소문자 구분 없이 AR로 시작하면 Array로 판정하고, 현재 Job BOM/Part List에서 관리자 Config 우선순위로 선택한 column의 저항을 읽습니다. 별도 Array Library나 Config 저항값은 사용하지 않습니다.

7.1 관리자 Config

"BOM": {
  "schemaVersion": 2,
  "colKey": ["Designator"],
  "arrayResistanceSourceColumns": [
    "Site Specification",
    "Technical Spec",
    "Description"
  ]
}

BOM은 외부 request의 CAE.PCB.BOM으로 선택합니다. colKey는 실제 header 목록이 아니라 논리적인 Designator key 선언이며 정확히 ["Designator"]를 사용합니다. 실제 RefDes header는 기존 Designator, Reference Designator, Reference alias를 지원합니다.

arrayResistanceSourceColumns는 파일 단위 우선순위입니다. 실제 header를 대소문자 구분 없이 비교하고 일반 공백과 구두점을 무시해 첫 match 하나를 모든 AR 행에 고정합니다. description은 Description과 일치하지만 [Option] Description은 일치하지 않습니다. 선택된 상위 column의 특정 행이 비어도 하위 column으로 fallback하지 않습니다.

후보 없음, Config 목록 누락·빈 값·정규화 중복, 실제 header의 정규화 중복은 모두 solve 전에 실패합니다. Config 우선순위와 실제 선택 header, BOM 파일의 경로·크기·수정시각·SHA-256을 실행 증거에 고정합니다.

기존 Config migration 기존 colKey=["Designator", "Site Specification"]은 자동 변환하지 않습니다. colKey=["Designator"]로 바꾸고 위 arrayResistanceSourceColumns를 추가해야 합니다.

7.2 선택 source column의 저항 추출

0.5OHM, 33OHM, 5.1OHM, 100OHM, 10KOHM, 3.3KOHM처럼 명시적인 OHM 단위가 붙은 유한한 양수 토큰만 사용합니다. 1 Ω 미만의 양수는 허용하지만 0OHM, -5OHM, Unicode minus를 쓴 −5OHM은 거부합니다. 품번 숫자와 (33), (5R1), (10K)는 값 후보가 아닙니다. 단위 토큰이 없거나 서로 다른 후보가 여러 개이면 해당 AR이 resolved path에 들어올 때 중단합니다.

7.3 실제 EDB Pin 기반 자동 Pin Map

실제 Pin자동 Pin Map
4핀, 이름 1..41-4, 2-3
8핀, 이름 1..81-8, 2-7, 3-6, 4-5

4핀/8핀 이외이거나 Pin 이름 집합이 정확한 1..N이 아니면 오류입니다. 예를 들어 AR900에서 3.3KOHM을 읽어도 실제 EDB가 2핀이면 resolved path에서 실패합니다. off-path AR은 수정하거나 전체 Job 실패 원인으로 삼지 않습니다.

7.4 CMP 충돌과 저장 후 검증

CMP 모델은 적용 전 비교 증거입니다. Case A(동일), B(없음/읽기 불가), C(충돌)를 기록하지만 세 경우 모두 BOM 저항과 자동 Pin Map의 R-only 모델을 다시 적용합니다. AEDB 저장·종료·재개방 뒤 모든 Pair와 R/L/C enable/value를 정확히 read-back합니다. BOM/행/토큰 변경이나 모델 drift는 publish 전에 실패합니다.

기존 root ARR 또는 BOM.compProp.ARR 설정이 남아 있으면 호환 입력으로 받아 제거하고 무시합니다. 그 안의 arrayPinMap과 resistanceOhm은 runtime 값으로 사용하지 않습니다. 별도 arrayResistorLibrary와 ARR 밖의 전기값 override는 지원하지 않습니다.

8. SYZ/TDR Option Profile

관리자 Config는 해석 수치를 직접 나열하지 않고 Job-local option 파일명을 Profile로 관리합니다.

"analysisOptions": {
  "defaults": {
    "syzProfileId": "SYZ_DEFAULT",
    "tdrProfileId": "TDR_DEFAULT"
  },
  "syz": {
    "SYZ_DEFAULT": {
      "sws": "SYZ_Default.sws",
      "sfsdf": "SYZ_Default.sfsdf",
      "sweepMode": "discrete",
      "computeExactDcPoint": false,
      "enforceCausality": false,
      "enforcePassivity": false
    }
  },
  "tdr": {
    "TDR_DEFAULT": {
      "file": "TDR_Default.json"
    }
  }
}
옵션 파일은 Job 폴더에서만 찾습니다 Profile에 적은 파일은 Job의 Setup/SWS/, Setup/SFSDF/, Setup/TDR/ 폴더에서만 찾습니다. 파일이 없거나 이름이 맞지 않으면 해석 전에 중단됩니다. 실제로 사용한 파일은 Run Config에 기록됩니다.

sws 파일명은 이 SYZ Profile 안에서만 설정합니다. Config 최상단에는 별도의 sws 항목을 두지 않습니다. 예전 Config의 최상단에 sws가 남아 있어도 해당 값은 무시되므로 실행을 막지 않습니다. Spec의 SYZ_Option이 비어 있으면 analysisOptions.defaults.syzProfileId가 가리키는 Profile의 sws를 사용합니다.

8.1 SYZ 설정

.sfsdf는 single/LIN/LINC/DEC 주파수 Grid만 저장합니다. sweepMode, interpolating일 때 interpolation.convergence/maxInterpPts, computeExactDcPoint, enforceCausality, enforcePassivity는 관리자 SYZ Profile에서 관리합니다. Exact DC와 Causality는 동시에 true로 둘 수 없습니다. JSON의 frequencySweep은 사용하지 않습니다.

Interpolating Sweep 설정 예시

sweepMode를 discrete에서 interpolating으로 바꿀 때는 같은 SYZ Profile에 interpolation 객체도 반드시 추가해야 합니다. sweepMode 값만 바꾸면 Config 검증 단계에서 중단됩니다.

"SYZ_DEFAULT": {
  "sws": "DCIR_Fast.sws",
  "sfsdf": "SYZ_Default.sfsdf",
  "sweepMode": "interpolating",
  "interpolation": {
    "convergence": 0.005,
    "maxInterpPts": 150
  },
  "computeExactDcPoint": false,
  "enforceCausality": false,
  "enforcePassivity": false
}
  • convergence는 SIwave에 전달하는 상대 오차 기준입니다. 유한한 양수로 적으며, 0.005는 0.5%에 해당합니다.
  • maxInterpPts는 Interpolating Sweep이 사용할 최대 point 수입니다. 양의 정수로 적고, .sfsdf 주파수 Grid의 전체 point 수를 넘지 않도록 합니다.
  • interpolation 안에는 convergence와 maxInterpPts 두 항목만 둡니다. discrete 모드에서는 interpolation 객체를 넣지 않습니다.
기존 option 파일명은 유지하십시오 위 예시의 sws/sfsdf는 기본 Profile 기준입니다. 다른 Profile을 사용 중이면 기존 파일명은 그대로 두고 sweepMode와 interpolation 설정만 변경하십시오.

자동 실행은 .sfsdf 파일을 읽어 각 행을 SIwave sweep 설정으로 적용합니다. SIwave 화면에서 파일을 직접 Load하는 것과 달리, 공개된 스크립트 명령에는 .sfsdf Load가 없기 때문입니다. 적용 결과는 해석이 끝난 뒤 실제 결과의 주파수 개수와 시작·끝 값을 파일에서 계산한 값과 대조해 확인하며, 다르면 실패로 처리합니다.

행 문법은 다음과 같이 해석합니다(2024 R2 실행에서 확인한 동작입니다).

  • 0Hz처럼 값 하나만 적으면 그 주파수 한 점입니다.
  • DEC 시작 끝 N은 로그 간격이며 N은 10배 구간당 점 수입니다. DEC 1Hz 10000000Hz 10은 7구간 x 10점에 시작점을 더해 71점이 됩니다.
  • LINC 시작 끝 N은 선형 간격이며 N은 총 점 수입니다.

점이 많을수록 해석 시간이 길어집니다. 신호가 중요한 대역만 촘촘하게 두는 구성을 권장합니다.

8.2 TDR 설정

Job의 Setup/TDR/에 두는 TDR option JSON에는 다음 네 항목을 적습니다.

{
  "riseTimePs": 50,
  "pulseRepetition": "20us",
  "pulseWidth": "10us",
  "timeDelay": "0.5ns"
}

차트 Y축 여유값은 별도로 core/config.json의 tdrReport.yAxisMarginOhm (기본 30 Ω)으로 정합니다. Target/Min/Max와 Far-end 차동 종단값은 Spec file에서 가져오고, Y축은 Spec Target ± yAxisMarginOhm으로 계산합니다. 차트 제목은 Group 이름이며, 표시 구간의 중앙에 AEDT native X Marker 한 개를 표시합니다.

차트의 표시 시간(view)과 해석 시간(stop)은 설정에 적지 않고 채널 배선 길이에서 자동으로 계산합니다. view는 신호가 채널을 두 번 왕복하는 시간에 rise time 여유 (10 × 50 ps)를 더해 0.5 ns 단위로 올린 값이고, 해석 stop은 view의 2배를 1.5 ns 단위로 올린 값입니다(최소 6 ns). 신호 속도는 0.149896229 mm/ps로 계산합니다. 실제 사용한 값은 Run Config의 tdr.transient.stopPs에 계산 근거와 함께 기록되고, CSV와 차트의 시간 범위도 이 값을 따릅니다. 이 계산식과 속도 값은 임시(provisional)이며 고객 확정 대기 상태입니다.

9. Port와 Reference Net/Layer

"ports": {
  "singleEndedImpedanceOhm": 50
}
항목설명
singleEndedImpedanceOhm각 Single-ended Port 임피던스. 100 Ω Differential Pair의 기본값은 50 Ω

나머지 Port 규칙은 설정 항목이 아니며 항상 같은 방식으로 적용됩니다.

  • 기준(GND) Net은 프로그램이 정합니다. nets.reference에 적은 이름은 참고용 힌트이고, 실제로는 설계 데이터(EDB)에서 Ground로 분류된 Net을 근거로 확정합니다.
  • Port는 신호 Pin이 실제로 놓인 층에 만듭니다.
  • Port의 수와 순서가 만들어질 Touchstone의 순서와 맞는지 해석 전에 확인합니다.

예를 들어 채널의 한쪽 끝이 Top층, 반대쪽 끝이 Bottom층에 있으면 각 Port는 자기 쪽 Pin이 있는 층에 +단자와 기준(GND) 단자를 함께 만듭니다. 설계의 Net 이름만으로 GND 후보를 하나로 정할 수 없으면 임의로 고르지 않고 해석 전에 중단하며, 어떤 후보가 있었고 왜 중단했는지 실행 기록에 남깁니다.

현재 제한 Ethernet connector-side PointTerminal 및 별도 GND 좌표 자동화는 이번 배포 범위에 포함되지 않습니다.

10.2 EDEN 결과 JSON 연동 상태

result[]의 TDRImage와 PCBImages는 배열이 아닌 파일명 하나입니다. PCB 미생성 시에는 null입니다. 각 Channel의 기존 중앙 X Marker 저항값이 Spec Target 범위 안이면 PASS(경계 포함), 아니면 NG이며 하나라도 NG면 전체 NG입니다. 해석 종료 코드 0과 전기적 PASS는 구분합니다. setting.json.stackup은 native AEDB에서 내보낸 stackup.xml을 참조합니다.

성공하면 10.1 표의 파일들이 그대로 outputs/에 공개됩니다. Web JSON 5종과 보드 전체 이미지·보드 참조 아카이브, Batch별 파일을 모두 outputs/ 바로 아래에 놓습니다. Array가 실제 적용된 Batch에는 고객 확인용 <Batch>_Array_Model_Result.json도 함께 놓이며, Array가 없는 Batch에는 만들지 않습니다. 그 밖의 중간 폴더나 temp/lock 파일은 만들지 않습니다. Web JSON의 JPG/CSV/Touchstone 참조도 이 공개 경로에 맞춥니다.

결과는 별도 폴더에서 먼저 완성하고 검증한 뒤 한 번에 outputs/로 이동(atomic rename)합니다. 이동 후에도 최종 폴더를 다시 검증하며, 진행 상태는 work/ 안에 기록됩니다.

result_detail.json 안에서는 채널 결과와 해석 묶음 결과를 다음과 같이 나누어 기록합니다. 실제 키 이름은 batchs가 아니라 batches입니다.

result_detail.json
├─ result[]   : 채널 하나씩의 상세 결과
└─ batches[]  : 함께 해석한 채널 묶음과 그 산출물
항목기록 단위주요 내용
